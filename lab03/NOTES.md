Отличия git restore от git restore --source=...
git restore берет версию файла из последнего коммита и восстанавливает в рабочую директорию
git restore --source=... указывает, из какого коммита или ветки взять версию
Все правки пропадут

Отличия revert от git reset --hard
git reset --hard отматывает историю назад, стирая ошибочные коммиты
git revert не трогает старые коммиты, а создаёт новый коммит, который делает противоположные изменения.
Почему в опубликованной истории безопаснее revert?
Если коммит уже отправлен на GitHub, другие разработчики могли скачать его. Если применить reset --hard и обновить ветку, сломается история
git revert добавляет новый коммит сверху

Тег — это статичная ссылка на конкретный коммит. Тег v1.0 всегда будет указывать на один и тот же момент в истории
Ветка — это динамическая ссылка. Когда мы делаем новый коммит, указатель ветки автоматически сдвигается вперёд на новый коммит
